# GitHub → Render: публикация проекта

Проект настроен по следующей схеме:

1. изменения отправляются в ветку `main` на GitHub;
2. GitHub Actions устанавливает зависимости, проверяет синтаксис и запускает тесты;
3. Render начинает публикацию только после успешных проверок GitHub;
4. если тесты не прошли, текущая рабочая версия на Render не заменяется.

## Что не попадёт в GitHub

Файл `.gitignore` исключает:

- `.env` и секреты;
- локальные базы `*.db`, `*.sqlite`, `*.sqlite3`;
- кеши Python и pytest;
- локальные виртуальные окружения и настройки редакторов.

Перед первой отправкой всё равно проверьте список файлов командой `git status`.

## Первая отправка в GitHub

Создайте на GitHub пустой репозиторий без README и лицензии. Затем в папке проекта выполните:

```powershell
git init -b main
git add .
git status
git commit -m "Initial MVP"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Замените `USERNAME/REPOSITORY` адресом созданного репозитория.

## Первое подключение Render

1. В Render выберите **New → Blueprint**.
2. Подключите GitHub и выберите репозиторий проекта.
3. Render прочитает `render.yaml` и предложит создать веб-сервис и PostgreSQL.
4. В переменных сервиса вручную укажите `TELEGRAM_BOT_TOKEN`.
5. Проверьте или задайте безопасный `ADMIN_PASSWORD`.
6. Запустите применение Blueprint.

Покупать домен не нужно: Render выдаст адресу проекта поддомен `onrender.com`.

## Обычная работа после подключения

```powershell
git add .
git commit -m "Краткое описание изменения"
git push
```

После `git push` проверки и публикация выполняются автоматически. Статус тестов виден во вкладке **Actions** репозитория GitHub, а статус публикации — в Render.

## Важное замечание

В CI используются только тестовые значения настроек. Настоящий токен Telegram и рабочие пароли должны храниться исключительно в переменных окружения Render, а не в GitHub и не в `render.yaml`.
